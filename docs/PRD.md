## 1. 背景与定位

earn10m 是一个公开记录 OPC（一人公司）从负债起点走向年赚千万目标的内容与数据产品。它把飞书多维表格中的日志、财务、业务线和内容记录同步为静态网站，并通过 Telegram 入口降低日常记录成本。

**[事实]** 当前实现是 Next.js 16 App Router 网站，包含首页、关于、财务看板、业务线和日志页面，并保留一套 /opc 路由。  
**[推断]** 产品的核心资产不是页面本身，而是“可核验的经营数据 + 连续的公开叙事 + 低摩擦记录工作流”。  
**[待确认]** 主要目标是公开品牌增长、个人经营驾驶舱，还是未来商业化产品；三者会影响隐私边界和指标优先级。

## 2. 目标用户与核心场景

### 2.1 用户

- OPC 创始人：记录每日行动、业务变化和财务结果。
- 公开读者：追踪真实进展、失败、方法与数据。
- 运营者：审核飞书数据、生成公开站点并控制发布。
- 潜在合作方：通过连续记录判断项目可信度和合作价值。

### 2.2 核心场景

1. 创始人在 Telegram 输入当天工作，系统整理后写入飞书。
2. 运营者从飞书同步日志、财务、业务线和内容数据。
3. 发布前执行数据校验与人工审查，再更新公开网站。
4. 读者按日期查看日志，并从看板理解目标进度和业务结构。
5. 负责人通过异常与趋势判断下一步经营重点。

## 3. 用户问题与产品价值

### 3.1 问题

- 日常记录分散，持续维护成本高。
- 经营叙事容易只讲结果，缺少可追溯过程。
- 财务、业务和内容数据分离，难以形成统一视图。
- 自动发布若缺少校验，会把错误或敏感数据直接公开。

### 3.2 价值

- 用统一数据源建立可信、可持续的公开记录。
- 把“记录—整理—同步—审核—发布”压缩为可重复流程。
- 让经营复盘从感受转向数据与证据。
- 将长期过程沉淀为品牌、内容和方法论资产。

## 4. 目标与非目标

### 4.1 产品目标

- 数据同步失败时明确失败，不用静默兜底伪装正常。
- 公开页面的数据具备来源、时间和口径说明。
- Telegram 入口可鉴权、可恢复、可观测。
- 发布动作默认需审核，自动发布必须显式开启。
- 建立覆盖数据解析、计算和发布守卫的自动化测试。

### 4.2 非目标

- 不在本阶段建设完整 ERP、会计或支付系统。
- 不让公开网站承担飞书原始数据的编辑职责。
- 不承诺收入目标一定实现，也不把预测包装成事实。
- 不在未定义脱敏规则前公开个人、客户或合作方隐私。

## 6. 功能需求与验收标准

| 编号 | 功能需求 | 验收标准 |
| --- | --- | --- |
| FR-01 | 飞书数据同步 | 四类导出均通过 JSON Schema 校验；任一失败时不覆盖上一份有效快照，并返回非零状态。 |
| FR-02 | 数据口径与新鲜度 | 每个页面展示最近同步时间；财务指标有口径说明；过期数据触发显著告警。 |
| FR-03 | 经营看板 | 收入、支出、负债、净资产、目标进度与业务线聚合可由固定样例精确复算。 |
| FR-04 | 日志浏览 | 日志列表和详情支持稳定 slug；重复日期有确定规则；缺失正文不会生成空详情页。 |
| FR-05 | Telegram 记录 | 仅允许配置的 Chat ID；异常不推进未完成消息的游标；重复 update 不重复写入飞书。 |
| FR-06 | AI 结构化 | AI 输出必须经过结构校验；解析失败保留原始输入并进入人工处理队列。 |
| FR-07 | 审核发布 | 同步与发布分离；发布前显示 diff、敏感字段扫描和数据质量结果；失败不得 git push。 |
| FR-08 | 可观测性 | 每次同步记录 run ID、开始/结束时间、数据量、失败阶段和最后成功快照。 |
| FR-09 | 配置管理 | Base/table 标识、CLI 路径与功能开关通过环境或受控配置注入，启动时校验。 |
| FR-10 | 恢复能力 | 可一条命令回退到上一份已验证数据快照，且不回退代码。 |

## 7. 非功能需求

- **正确性：** 金额使用明确单位；关键聚合测试误差为 0；非法数字不得转为 0 混入结果。
- **安全：** 生产依赖无已知高危漏洞；秘密不进仓库、日志或命令行；公开字段执行白名单。
- **可靠性：** 同步原子化；重复执行幂等；发布失败可恢复。
- **性能：** 静态页面 P95 首屏加载目标小于 2.5 秒；常规同步目标小于 5 分钟。
- **可维护性：** 有真实 README、环境模板、测试入口和数据契约；禁止绝对用户路径。
- **隐私：** 财务、客户和个人信息按“公开 / 内部 / 禁止同步”分级。
- **可访问性：** 核心页面键盘可操作，颜色不是唯一状态表达。

## 8. 成功指标

### 北极星指标

- 每周“有效公开记录天数”，有效指数据通过校验且读者可访问。

### 质量与运营指标

- 同步成功率 ≥ 99%。
- 数据新鲜度 P95 ≤ 24 小时。
- 非法数据进入公开站点次数 = 0。
- Telegram 重复写入率 = 0。
- 发布回滚率 < 2%。
- 每周记录完成率 ≥ 80%。
- 公开日志到业务行动的引用率逐月提升。

## 10. 风险与依赖

- 飞书 CLI 的输出格式或权限变化会中断同步。
- Telegram、Claude CLI 和 Vercel/Git 集成是外部依赖。
- 自动生成内容可能包含错误、隐私或不适合公开的信息。
- 财务公开存在声誉、法律和人身安全风险。
- 目标叙事如果缺少口径与证据，可能损害可信度。

## 12. 2026-07-12 二次复核增量

### 新证据

- 自动同步在基线后再次运行，4 个 `src/data/feishu/*.json` 仍被写成 Markdown 表格输出，均无法作为 JSON 解析。
- `auto-deploy.sh` 已具备锁、显式 `--publish`、精确 stage、无关变更检查和发布前 JSON 校验，因此能够阻止错误数据被推送。
- 但校验发生在 `sync-feishu.sh` 已经覆盖正式数据路径之后，本地上一份有效快照没有被保护；这是“发布安全”通过而“数据恢复”失败。

### PRD 升级决定

1. FR-03、FR-07、FR-10 的验收顺序固定为：临时目录导出 → JSON/schema/业务不变量 → diff/敏感字段 → 原子替换 → 可选发布。
2. 同步失败时，正式数据目录和 `last-good` 快照必须保持字节级不变，并记录 run ID、失败阶段和源输出摘要。
3. 构建与发布只能读取最近一次已验证快照；禁止为了“保持更新”而读取本轮失败产物。
4. 在此原子同步门禁通过前，项目状态保持“修复后试点”，不得把页面更新视为真实经营数据更新。
