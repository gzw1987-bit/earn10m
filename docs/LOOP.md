## 3. 闭环流程

### Observe

收集：

- 飞书表 revision、记录数、字段签名和最新更新时间。
- 同步命令状态、JSON 校验、数据 diff、敏感字段命中。
- lint、类型检查、构建、测试和依赖审计。
- 线上路由可用性、错误率和数据新鲜度。

输出：带 run ID 的观察包，不做主观结论。

### Orient

将观察结果按四类归因：

1. 数据源或权限；
2. 导出与转换；
3. 页面计算与呈现；
4. 发布与运行环境。

区分事实、推断和待确认，不把空数据等同于真实的零。

输出：根因假设、影响范围、风险等级和可复现实例。

### Decide

按“数据错误与泄露 > 安全漏洞 > 不可用 > 体验问题”排序。每轮只选择可在一个短周期验证的目标，并写明：

- 负责人；
- 预期结果；
- 验收命令；
- 回滚条件；
- 不在本轮处理的范围。

输出：本轮交付卡和冻结的验收标准。

### Act

在短分支中完成最小改动：

- 先加失败用例或数据样例；
- 再修实现；
- 更新运行文档和配置模板；
- 不混入内容更新或无关重构。

输出：代码/配置 diff、迁移说明和操作记录。

### Verify

至少通过：

1. JSON Schema 和业务不变量；
2. 单元、集成、端到端冒烟；
3. lint、类型、构建；
4. 生产依赖审计；
5. 公开字段与秘密扫描；
6. 预发布页面人工抽查；
7. 回滚演练。

输出：可复现的验证证据和最终发布决定。

### Learn

发布后 24 小时复查数据、错误和用户反馈。把事故或偏差转成：

- 新测试；
- 新监控；
- 新数据契约；
- PRD 决策记录；
- 下一轮 backlog。

输出：一页复盘，包含“预期 / 实际 / 差异 / 根因 / 永久措施”。

## 5. 质量门禁

### 数据门禁

- 所有导出可解析并符合版本化 Schema。
- 记录数异常变化超过阈值必须人工确认。
- 金额、日期、状态和 ID 满足业务不变量。
- 任何解析失败不得降级成“正常零值”发布。

### 工程门禁

- lint、类型检查、构建和测试全部通过。
- 核心计算具备固定样例断言。
- 生产依赖无高危漏洞；中危有书面接受期限。

### 安全与发布门禁

- 秘密扫描无命中。
- 公开字段白名单通过。
- 发布 diff 只包含预期数据目录。
- 有上一有效快照和已验证回滚命令。

## 6. 反馈指标

- 同步成功率、平均恢复时间、连续失败次数。
- 数据新鲜度、记录数漂移、字段契约变更次数。
- 预发布拦截数、线上数据事故数、回滚次数。
- Telegram 处理成功率、重复写入率、人工接管率。
- 日志阅读、回访和经营行动引用率。
